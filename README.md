# לוח התייצבות · אגף הדרכה

לוח לייב למפקד אגף ההדרכה: כמה אנשים יש היום באתרים, אילו השתלמויות פעילות, ומי מהמגמות דיווח.
כל מנהל מגמה מקבל קישור אישי, מדווח מהטלפון עד 10:00, והלוח מתעדכן מיד אצל כולם.

- **האתר** יושב ב-GitHub Pages (חינם), עם קישור קבוע.
- **הנתונים** נשמרים ב-Supabase (מסד נתונים Postgres, חינם בהיקף הזה). הם לא נשמרים ב-GitHub.
- **בלי הגדרות** (כש-`config.js` ריק) האתר עובד במצב הדגמה עם נתונים בדויים, כדי שאפשר יהיה לראות אותו מיד.

## מה יש בתיקייה

| קובץ | מה הוא |
|---|---|

## התקנה, צעד אחר צעד

> הדרך הקלה: פותחים את התיקייה הזו ב-Claude Code ומדביקים את התוכן של `CLAUDE_CODE.md`. הוא יעשה את שלבים 1 ו-5 ויסביר את השאר.

### 1. לראות את האתר במחשב (2 דקות)
בתיקייה הזו מריצים:
```
npx serve .
```
ופותחים את הכתובת שמופיעה. זה מצב הדגמה, עם נתונים בדויים שנשמרים רק בדפדפן.

### 2. פתיחת פרויקט ב-Supabase (5 דקות)
1. נכנסים ל-[supabase.com](https://supabase.com), ונרשמים או מתחברים.
2. **New project**. נותנים שם (למשל `hadracha-board`), סיסמה חזקה למסד הנתונים (שומרים אותה), ובוחרים **Region: Central EU (Frankfurt)**.
3. מחכים כדקה שהפרויקט יוקם.

### 3. מילוי `config.js`
ב-Supabase: **Project Settings ← API**. מעתיקים:
- **Project URL** → אל `SUPABASE_URL`
- **anon public** key → אל `SUPABASE_ANON_KEY`

> מפתח ה-anon מיועד להיות ציבורי. ההגנה על הנתונים היא בהרשאות שבמסד הנתונים. **לעולם אל תשימו בקובץ את מפתח ה-`service_role`.**

### 4. יצירת הטבלאות
ב-Supabase: **SQL Editor ← New query**. מריצים לפי הסדר: `sql/01_schema.sql`, `sql/02_seed.sql`, `sql/03_permissions.sql`, `sql/04_upgrades.sql`.

### 5. העלאה ל-GitHub והפעלת האתר
עם Claude Code (או ידנית):
```
git init && git add . && git commit -m "לוח התייצבות אגף הדרכה"
gh repo create hadracha-board --public --source . --push
gh api -X POST repos/{owner}/hadracha-board/pages -f "source[branch]=main" -f "source[path]=/"
```
אחרי דקה-שתיים האתר זמין בכתובת `https://<שם-המשתמש>.github.io/hadracha-board/`.

> **ריפו ציבורי** פירושו שהקוד גלוי. הנתונים לא נמצאים בקוד ולכן הם לא גלויים. GitHub Pages מריפו פרטי דורש חשבון בתשלום.

### 6. כתובת האתר ב-Supabase (כדי שהכניסה במייל תעבוד)
ב-Supabase: **Authentication ← URL Configuration**:
- **Site URL**: כתובת האתר משלב 5
- **Redirect URLs**: מוסיפים את אותה כתובת, וגם `http://localhost:3000` לבדיקות

### 7. כניסה ראשונה והגדרת המגמות
1. פותחים את האתר, מקלידים את המייל שלך ולוחצים **שליחת קישור כניסה**.
2. פותחים את הקישור מהמייל **באותו מכשיר ובאותו דפדפן**.
3. **מי שנכנס ראשון הופך אוטומטית למנהל המערכת.** לכן כדאי שזה יהיה אתה, מיד אחרי ההתקנה.
4. בלשונית **דיווחי מגמות**: בכל כרטיס לוחצים ⋮ ← **עריכה** וממלאים שם מנהל וטלפון.
5. שולחים לכל מנהל את הקישור שלו: ⋮ ← **שליחה בוואטסאפ** (או **העתקת קישור אישי**).

**הוספת מפקד האגף כמנהל מערכת:** הוא נכנס פעם אחת עם המייל שלו (יראה הודעה שאין לו הרשאה). אחר כך מריצים ב-SQL Editor:
```sql
insert into public.admins (user_id, email)
select id, email from auth.users where email = 'המייל-שלו@example.com';
```

## הרשאות

הרשאות מנהלים בלשונית **הרשאות**. רק מנהלי מערכת רואים אותה.

| הרשאה | מה אפשר לעשות | איך נכנסים |
|---|---|---|
| **מנהל מערכת** | הכול, כולל ניהול מגמות והרשאות | מייל וסיסמה בלבד |
| **עורך** | צפייה, דיווח על כל המגמות והוספת השתלמויות | מייל וסיסמה, או קישור אישי |
| **צופה** | צפייה בלבד | מייל וסיסמה, או קישור צפייה |
| **מנהל מגמה** | צפייה, ודיווח רק על המגמה שלו | הקישור מהכרטיס של המגמה |

- **קישור אישי:** נוצר בלחיצה. אפשר להעתיק אותו, לשלוח בוואטסאפ, ליצור קישור חדש (הקודם מפסיק לעבוד) או להסיר.
- **מייל וסיסמה:** מוסיפים את המייל בלשונית "הרשאות". האדם נכנס לאתר, לוחץ **פעם ראשונה? יצירת סיסמה**, ומאשר את המייל שהוא מקבל.
- אי אפשר להסיר את עצמך, ותמיד נשאר לפחות מנהל מערכת אחד.
- המסד מוגדר בשני קבצים: `sql/01_schema.sql`, ואחריו `sql/03_permissions.sql`.

## ימים מיוחדים
בלשונית **ניהול** ← **ימים מיוחדים**:
- **הוספת חגי ישראל לשנה הקרובה** מסמנת את ימי החג בימי עבודה: ראש השנה, יום כיפור, סוכות, שמחת תורה, פסח, שביעי של פסח, שבועות ויום העצמאות. התאריכים מחושבים לפי הלוח העברי.
- **יום מיוחד ידני**: "אין דיווח" או "שעת סגירה אחרת" (למשל ערב חג עד 12:00).
- ביום "אין דיווח" אף מגמה לא מסומנת כחסרה.

## גיבוי יומי
התיקייה `hadracha-backups` היא ריפו **פרטי** נפרד. GitHub Actions מגבה בו כל לילה את כל הטבלאות, וגם שומר על פרויקט Supabase פעיל. ההוראות נמצאות ב-README שלה.

## גיבוי וייצוא
- בלשונית **מגמות לאורך זמן** ← **הורדה לאקסל** (קובץ CSV).
- ב-Supabase: **Table Editor** ← בוחרים טבלה ← **Export to CSV**.
- גיבוי אוטומטי יומי: ראו "גיבוי יומי" למעלה.
